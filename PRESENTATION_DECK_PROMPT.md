```markdown
Create a 10-slide, high-converting hackathon pitch deck for "PRISM", an autonomous AI workspace and generative application platform.

---

### Global Design Guidelines
- Color Palette:
  - Primary Background: Sleek Dark (#0F0F12) with champagne/cream accents (#FAF8F5).
  - Cards & Containers: Glassmorphism (#FFFFFF10, border #FFFFFF15, backdrop-blur-md).
  - Accent Gradients: Neon Violet to Electric Indigo (linear-gradient(135deg, #6366F1, #8B5CF6, #EC4899)).
  - Text: Bright White (#FFFFFF) for headings, muted zinc (#A1A1AA) for body text.
- Typography: Inter or Plus Jakarta Sans. Bold, punchy headings with high contrast.
- Visuals: Clean system diagrams, UI wireframe mockups, comparison tables, and metric callout cards.

---

### Slide 1: Cover & The Hook
- Header: PRISM
- Subtitle: The Intent-to-Interface Adaptive AI Workspace
- Tagline: "Imagine it. Run it live."
- Highlights: Apps that remember. Agents that reason. Workflows that keep running.
- Footer: Hackwave 3.0 | PS4: Adaptive Workspace | Team PRISM

### Slide 2: The Core Problem: The Fragmentation Tax
- Headline: Modern Productivity is Broken
- 3 Pain Points (Card Layout):
  1. The SaaS Sprawl: Teams bounce between 7+ disconnected tools (CRM, Linear, Notion, Slack, Zapier).
  2. The Blank Canvas Trap: No-code platforms require hours of manual configuration before delivering any value.
  3. Rigid, Static Interfaces: Traditional software cannot reshape itself around user intent.
- Callout Metric: "Knowledge workers lose 4.2 hours every week simply context-switching between tools."

### Slide 3: The PRISM Solution: Unified Context Loop
- Headline: Software That Assembles Itself in Real Time
- Visual: Infinite Circular Loop Diagram (Workspace DNA):
  - Memory: Relational Postgres + Document Tree
  - Intelligence: Autonomous AI Agents with Tool Calling
  - Execution: Durable Visual Workflow Automations (DAG)
  - Interface: Fluid Multi-View Adaptive Canvas
- Core Differentiator: One single prompt generates the database schema, custom agents, and automated workflows in under 3 seconds.

### Slide 4: System Architecture (TSK-1 Kernel)
- Headline: TSK-1: The Task System Kernel
- Architecture Flow:
  - Layer 1 (Client): Next.js 15 App Router + React Flow + Tailwind CSS
  - Layer 2 (Orchestration Engine): Gemini 3.5 LLM with Multi-Tier Selector (FAST, STANDARD, REASONING)
  - Layer 3 (State & Memory): Supabase PostgreSQL (Hierarchical `node_items`, `agents`, `workflows`)
  - Layer 4 (Execution): Durable workflow DAG runner + Embeddable widget endpoint (`embed.js`)
- Badge: "Zero Hallucination Guaranteed via Strict JSON Schema Validation"

### Slide 5: The Multi-View Workspace Engine
- Headline: One Single Dataset. Infinite Perspectives.
- 4-Quadrant Visual Grid:
  - ≡ Hierarchical List: Drag-and-drop bullet indent/outdent, rich tags, @mentions.
  - ⊞ Kanban Board: Column-based card pipeline with customizable stages.
  - ⑂ React Flow Mind Map: Dynamic visual node graph rendering document relationships.
  - ⊞ Action Table: Structured spreadsheet with typed columns (Select, Date, Priority).
- Key Feature: Instant switching with zero latency; all views share unified node memory.

### Slide 6: Autonomous AI Agents & Tool Execution
- Headline: Agents That Don't Just Chat—They Execute
- Features:
  - Custom Workspace Personas: Auto-configured based on app type (e.g., Sales Concierge, Code Sentinel).
  - Context-Aware Memory: Reads live project nodes directly from the active project.
  - Tool Calling Capabilities: Agents query tables, generate sub-tasks, and dispatch external webhooks.
  - Public Distribution: Deployable chat widgets embeddable via 1 line of JavaScript.

### Slide 7: Visual Workflow Automation Engine
- Headline: Visual DAG Builder & Durable Execution
- Diagram / Flowchart:
  [Event Trigger: Item Marked Critical] ➔ [AI Action: Generate Executive Brief] ➔ [Webhook Action: Alert Slack / Email]
- Core Strengths:
  - Event triggers: Schedule, Webhook, Database item change, Manual trigger.
  - Durable execution: Step retry logic, exponential backoff, run logging in `workflow_runs`.

### Slide 8: Live Demonstration Scenario
```
